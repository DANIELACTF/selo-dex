PASSO 1

A planilha

Comece pela carteira que já existe, para não refazer nada.

  1. No Drive: Novo → Upload de arquivo → Carteira_Tributaria_Fiscal.xlsx.

  2. Abra o arquivo enviado → Arquivo → Salvar como Planilhas Google. É o formato que o Apps Script consegue editar.

    As fórmulas COUNTIF do “Resumo Equipe” sobrevivem à conversão — continuam recalculando sozinhas.

  3. Renomeie para algo como Onboarding Fiscal — Moraex.

Não dá para rodar no .xlsx direto: o Apps Script só edita planilhas no formato do Google. A conversão é obrigatória.

PASSO 2

O código

Na planilha: Extensões → Apps Script. Apague o Código.gs de exemplo que vem junto.

São duas coisas diferentes, e confundir as duas é o erro mais comum: o manifesto, que já existe e você só substitui, e os {{N_ARQUIVOS}} arquivos de código, que você cria.

Primeiro: o manifesto

Não crie um arquivo novo para ele. Se você criar um Script chamado appsscript.json, o editor vira isso em appsscript..gs e tenta ler JSON como JavaScript — dá SyntaxError: Unexpected token ':' na linha 2. Se já aconteceu: apague esse arquivo (⋮ → Excluir) e siga os passos abaixo.

  1. Menu da esquerda → ⚙️ Configurações do projeto.

  2. Marque “Mostrar arquivo de manifesto appsscript.json no editor”.

  3. Volte para Editor. O appsscript.json agora aparece na lista — ele sempre esteve lá. Abra, apague o conteúdo e cole o de baixo.

{{CARD_MANIFESTO}}

Depois: os {{N_ARQUIVOS}} arquivos de código

Atualizando o app? Quando um item novo aparece no menu, o Menu.gs mudou junto — ele é quem monta o menu, e é o arquivo mais esquecido nas atualizações. Depois de colar, recarregue a planilha (F5): colar código no editor não atualiza o menu da aba que já está aberta.

Faltou um arquivo? O app diz qual — “Falta colar o arquivo Pastas no Apps Script”. Para ver tudo de uma vez: menu Configurar · v{{VERSAO}} → Conferir instalação.

Para cada um, clique no + ao lado de “Arquivos”, escolha o tipo indicado, dê o nome exato sem a extensão (o editor põe o .gs ou .html sozinho) e cole o conteúdo. A ordem não importa — o Apps Script carrega todos antes de executar qualquer coisa. Marque conforme for fazendo; a marcação fica salva neste navegador se você precisar parar no meio.

PASSO 3

Primeira execução

  1. No editor do Apps Script, menu da esquerda → Serviços → + → escolha Drive API → Adicionar. É ele que converte o PDF do e-mail em texto.

  2. Volte para a planilha e recarregue a página. O menu 🏢 Onboarding Fiscal aparece na barra de cima.

  3. Configurar → Criar/conferir abas. O Google vai pedir autorização — é a primeira execução.

    Vai aparecer “Este app não foi verificado”. Clique em Avançado → Acessar (não seguro). “Não verificado” aqui significa que o app é seu e não passou pela revisão pública do Google — não que tenha algo errado com ele.

  4. Teste com 1 · Processar e-mail, anexando o e-mail salvo em PDF.

HONESTIDADE

O que ainda não foi testado ao vivo

A lógica do app tem testes automatizados rodando contra os e-mails reais da Thays — inclusive o OCR de verdade das páginas do PDF. O que segue abaixo está escrito e revisado, mas só se prova na sua execução:

  1. A conversão do PDF pelo Drive. O que é testado aqui é tudo em volta: a montagem da chamada, o descarte da conversão temporária, os formatos aceitos e cada caminho de erro.

  2. As consultas à Receita. O ambiente de desenvolvimento bloqueia receita.fazenda.gov.br e brasilapi.com.br.

  3. O OCR do comprovante rende pouco. Medido no seu PDF de 27/08: CNAE aproveitável em 2 das 7 empresas. Por isso o CNPJ e a razão social nunca saem dele — vêm da linha do e-mail — e a consulta tem precedência.

  4. O drive de rede continua fora do alcance. As pastas no Google Drive o app cria; as da rede saem pelo CSV mais o script do PowerShell, rodado no servidor.
